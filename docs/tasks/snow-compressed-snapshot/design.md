# Boundary and approach

Build/runtime packaging only. Add a small snow-owned snapshot helper under catalogs/fresh-powder/src/aggregator/, use it from scripts/vercel_build.py after existing validation/compaction, and initialize the runtime path in root app.py before aggregator.web.app imports DB defaults. Change vercel.json to explicitly include the gzip/manifest and exclude the uncompressed bundled DB. Add meaningful tests in the existing test layout. Root owns task/release docs and actual publication.

Keep the build source DB intact, including the byte-preserving skip-download path. Compression writes an atomic deterministic gzip plus a manifest of original SHA256/byte count. Runtime uses a digest-named file in the temporary directory, streams decompression to a unique temporary file, verifies exact byte count and SHA before atomic replacement, cleans failure temporaries and reuses only a verified existing copy. Serialize extraction per digest with an OS advisory lock and recheck the verified cache under that lock so concurrent initializers need only one large temporary DB. Do not modify downloaded release history or copy auth databases. An explicit DATABASE_PATH wins; ordinary uncompressed local development continues. No runtime network or schema migration.

Use the compressed artifact only as a packaging representation of the exact prepared DB. Under the digest lock, remove only abandoned extraction temporaries bearing that digest; leave all other snapshots and files untouched. Choosing a compressed snapshot forces read-only DB access even outside Vercel. No observation cleanup, schema redesign or new hosted database. Test propagation to actual DB consumers and health, not just compression helpers. Do not remove other caches or read local deployment/credential files during checks.

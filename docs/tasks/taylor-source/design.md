# Change boundary

Taylor exposes listing metadata in HTML and exact purchasable records in the product page's JSON literals (`skusKeyValues`, option keys and display labels). Listing IDs are different from detail SKU IDs. Listing pages can render cumulative pages; `__productCount`, requested page/per-page and unique listing IDs must agree before a collection is considered complete. The site's explicit Show All option is a valid bounded collection request, not evidence that a truncated response is complete.

Reuse common `Product`/`VariantOffer`, catalog classification, request pacing/retries, atomic source snapshots, selected-offer queries and merchant audit gates. Expected implementation paths: a source-specific parser in `common/deal_common/parsers/taylor.py`; a small optional detail-page hook in `BaseParser` and the shared HTTP loop; catalog refresh/destination/audit dispatch; the tools source definition; fixture tests. Listing metadata is only discovery input, never a purchasable variant. Pass the existing catalog classifier as a pre-detail selector so accessory pages do not require unnecessary requests; classify authoritative details again before saving.

The adapter must decode JSON literals without evaluating merchant JavaScript. Source-specific option mapping and URL validation belong in the adapter. Shared code must not import a catalog. Preserve exact raw option descriptions, reject ambiguous/default selections that cannot be encoded in the destination, reject unknown stock and non-USD or nonfinite prices, and do not infer historical selling prices from the retailer reference. No browser authentication, cart mutation, anti-bot bypass or partner signup is in scope.

First validate the real multi-SKU URL contract and collection completeness. If those cannot be established, retain an explicit held-source receipt rather than admitting an incomplete or misleading source. Integration should not weaken Shopify or Grizzly destination checks. No large generic adapter framework is needed.

Live browser checks confirmed the no-option grinder SKU and an `a_21=v_6294` selectable product. Taylor's explicit Show All view returns all 1,917 advertised listings. Opaque variant identity will retain both selector SKU and canonical option query, so normalization can reject a destination with different options without inventing a Shopify variant parameter. Detail breadcrumbs supply product taxonomy. Discovery also exposed plural drill/router/driver bits admitted from title-only metadata; add the narrow accessory guard and positive powered-kit regressions before source admission.

Final discovery found four distinct listing IDs aliasing existing canonical URLs. Validate listing IDs against the advertised total, then deduplicate detail destinations. The workshop collection is probed separately before deciding whether it adds eligible equipment; its count is not folded into the completed power-tools receipt.

# Boundary and design

The gap lives in source discovery and exact-offer decoding. Existing browser-only extraction sees listing-wide prices. Its explicit next-page selector misses the current markup, while its generic numbered-link fallback can traverse it; no current coverage failure is assumed. The older static parser uses obsolete selectors. Replace that decoding with a reusable source-specific parser under `common/deal_common/parsers/thecircle.py`, retaining an import compatibility shim at the former snow path if useful. Common must not import the snow catalog.

Use `BaseParser.requires_product_pages` and the existing `get_product_evidence_url` / `parse_product_evidence` hooks. The listing yields discounted product families from `.prod-card[data-product-id]` with explicit CAD prices; product HTML plus the documented `.ajax` endpoint supplies the variant set. Preserve the separate canonical family URL and exact merchant-provided `?id=` destinations. No new generic fetch orchestration, browser-control code, schema, price matching or fuzzy identity machinery is needed. Keep the existing 500-detail budget, bounded pages, pacing and fail-closed outcomes. The configured canonical hostname is `www.thecirclewhistler.com`; source activation must align the existing exact-host guard rather than weaken it.

Validate listing active page against the requested path, next page sequence, stable advertised terminal page, unique discovery IDs and proper termination. A singleton/full-price collection can have no pager; malformed or contradictory collection state is not success. Avoid fetching full-price discovery entries; deduplicate families across both collections through the existing fetcher. Do not silently truncate variants. The full source profile will establish whether existing budgets suffice.

Reconcile HTML canonical URL/title, selected form product/variant and money, explicit CAD evidence, variant DOM IDs/options/availability, JSON canonical/product/variant identity, and each variant's own prices, stock and image. Confirmed stock requires explicit available/on_stock, tracked positive quantity and no backorder/delivery conflict; inconsistent evidence fails, unavailable variants cannot be admitted as stock. Preserve unknown status and meaningful delivery notices where evidence is incomplete but identity/money remain certain. Inspect actual source shapes before implementing fallbacks. Theme descriptions are untrusted data and must not be executed.

Root owns raw primary captures, full bounded discovery/profile, candidate execution/audit and public-snapshot/rollout verification. Implementer owns parser, offline fixtures/tests and status. Activate config/registry only after admission and independent review. The unchanged browser extractor can remain available for rollback; its limitations are not evidence of a complete source.

# Boundary

Current common catalog query uses (-discount, -savings, price, key). Snow selection_sql instead orders equal percentages by current price, and default card order uses image availability before savings. Snow _products_to_deals also seeds the cheapest tied variant. For mixed-currency default card queries, exact percentage remains first, followed by an explicit USD-first currency group and then currency code before comparing cash savings. The existing database currency field is used directly; unknown values are not coerced to USD. This avoids nominal USD/CAD money comparisons. Invalid sort fallback uses the same complete default order. Align these three decisions in their existing owners: aggregator/offers.py, db.py default sort map, scraper.py _products_to_deals best key. Preserve decimal percentage calculation and existing identity, stock, filtering and history behavior. No broad shared ranking abstraction is needed for SQL and Python expressions.

Tests belong in existing snow offer/query regression modules. House parser/HTTP work is separate and must be preserved; its registry edit is already committed locally. No source configuration or browser work in this task.

# Evidence and implementation boundary

The normal collection SHOW MORE control requests `https://services.mybcapps.com/bc-sf-filter/filter` with public parameters `shop=skiess-test.myshopify.com`, `collection_scope`, `page`, `limit=48`, `variant_available=true`, `h_options=hide`, `build_filter_tree=true`, `check_cache=true`. The collection identity is in the page's JSON string passed to `window.__reactRouterContext.streamController.enqueue`; decode JSON data only, never execute JavaScript. The route `routes/collections.$handle` exposes the collection ID and handle.

The API carries variant IDs, merged option names/values, SKU, availability, inventory quantity, USD prices and compare-at prices. Product metadata `online_variant_prices` maps the actual online price by SKU; `online_variant_lowest_price` supplies an explicit currency, while the lowest price alone cannot be copied across variants. Product pages expose `onlinePrice`, `variants.nodes`, selected options and JSON-LD offers for independent matching.

Observed example: 2024 XO H21, reference $1,250, online $199. Sizes 166 and 178 are selectable; 172 changes the button to SOLD OUT. The real destination uses `?ski+size=178`, not Shopify's ordinary `variant` query. The product table's ordinary price remains $1,250, so using it would lose the sale. Conversely, Bundle Product entries can have zero base prices, negative inventory and configurable components; exclude these until independently supported.

Smallest implementation: a source-specific common parser returning the existing Product/VariantOffer types, registry/config changes for this snow source, and deterministic fixtures/tests. Reuse the existing paced HTTP fetcher and pagination failure handling. Avoid a new generalized feed framework. Keep the current browser extractor available as historical implementation; do not silently fall back after a failed candidate refresh.

Decode only the required route/collection identity with bounds/cycle checks. The initial collection page discovers the fixed provider endpoint and collection ID; subsequent API pages reconcile total, page size, terminal count and unique IDs. Freeze expected count per traversal; changing totals or truncated/repeated pages invalidate the source. Do not trust an arbitrary URL from metadata.

Validate currency and finite positive price/reference per selected SKU. Preserve explicit product taxonomy and condition tags. Require actual stock evidence; availability conflicts, missing stock or delayed fulfillment stay unknown and cannot pass exact size. Support only option-name mappings verified in the storefront. Keep product canonical identity stable while selecting option-specific purchase links; never rewrite earlier history.

Task-owned public research artifacts are in `.local/source-expansion/skiessentials-variants-20261104/`. The complete feed probe reconciled 1,857 collection listings across all six collections. The production HTTP traversal then completed 48 responses without errors, producing 482 unique eligible products and 1,251 exact offers. All 30 independently audited offers also match this candidate. Configuration now selects the admitted HTTP adapter; live rollout verification remains required.

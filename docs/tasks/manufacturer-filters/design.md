# Smallest implementation boundary

`Catalog.brand_aliases` already owns catalog-specific explicit mappings. `normalize` currently applies them only at ingestion. `query` compares raw stored labels before filtering, and `read_offer_history` compares manufacturer text without the catalog map. Adding ingestion aliases alone would leave current pages inconsistent and make older observations disappear after the next refresh.

Extend the existing common manufacturer identity helper with an explicit alias input, preserving its fulfillment-label rejection and unknown-name behavior. Pass catalog aliases into the query and history paths. Query should project canonical brand values without mutating source rows or offers, apply the canonical requested brand before filtering/counting/pagination, expose one canonical facet and retain raw-brand free-text matches. Web form state, applied filters and pagination must use the same canonical requested label. History compares both old and current brand through the same explicit map while retaining every other exact identity guard; presentation can use the canonical label without rewriting storage.

Source fingerprints continue describing the actual public snapshot bytes/rows. Do not canonicalize the sources used by health hashing or mutate history. Ingestion uses the common helper instead of its separate lookup. Optional alias inputs must preserve existing callers when omitted. Root supplies verified catalog alias tables and research; implementation owns common behavior/tests. No source transports, money/ranking, size equivalence, schema, alerts or fresh scrape changes.
